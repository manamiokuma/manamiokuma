# 日繰り — 引き継ぎ資料

最終更新：2026年9月8日
対象ファイル：`higuri.html`（単一ファイル・依存ライブラリなし・外部への通信は文字（フォント）だけ）

書き上がった小説をpixivに毎日投稿していくための、在庫の台帳。
`shuire.html`（朱入れ）が「原稿を直しきる」道具なら、こちらは「直った原稿を切らさず出しつづける」道具。

## 答える問いは三つだけ

1. いま手元に、投稿できる作品が何本あるか
2. そのうち予約に入れ終わったのは何日ぶんか（＝あと何日で在庫が切れるか）
3. 次に検査・分割すべきはどれか

起動して最初に出るのは、二つめの答え（「予約ずみ　あと◯日ぶん」）ひとつだけ。
残りが3日を切ると朱の帯が出る。閾値は控えの画面で変えられる。
三つめは「次の手」として、日付のない話・pixivに未入力の予約・未検査の作品の順に、最大三行。

## やらないこと

- **pixivとXへの自動投稿はしない。** pixivに投稿用の公式APIはなく、非公式の道はcookieとUAを
  直に扱うことになる。8年ぶんの作品が乗っているアカウントで負える賭けではない。
  実際の投稿はpixivの予約投稿機能に手で入れる。この道具は段取りだけを持つ。
- **外部APIへの接続・スクレイピング・自動ログインを足さない。**
- **原稿の文体検査はしない。** それは `manuscript-qa` の仕事。ここは「検査を通したか」の印だけ持つ。
- **本文テキストを扱わない。** 分割は話数・字数・タイトル・R-18区分だけで行う。

## 二つのフラグを混ぜない

| 印 | 意味 | どこで押すか |
|---|---|---|
| `checked` | 文体検査＋目視を通した | 話の画面／分割の画面 |
| `reserved` | pixivの予約に実際に入れ終えた | 予定の画面のチェック |

**検査済で未予約の話が「仕込み待ちの在庫」**であり、この区別がこの道具の中心。
ダッシュボードの二つめの数字はこれを数えている。

## かたち

作品（Work）：`id` `title` `fandom` `totalChars` `status`（未検査／検査済／投稿済／保留）
`isBook` `note`。`isBook` が立っている作品は一覧で「本にする ─ pixivには出さない」の帯が付く。

話（Episode）：`id` `workId` `index` `title` `chars` `isR18` `checked` `caption` `tags`
`scheduledAt` `reserved`。分割しない作品も1話として1件持つ（特別扱いしない）。
`scheduledAt` は `2026-09-08T19:00` の形の文字列で、時刻まで持つ。

## 保存

`novel-queue:data` ひとつのキーに、全体をJSONで入れる。作品・話・設定を別キーに散らさない
（保存先にレート制限があり、細かい読み書きの繰り返しに向かないため）。

保存先は起動時に上から順に探す。

1. `window.storage`（ホスト環境のキー・バリューストア）
2. Artifactの `db` 機能（`claude.use("db")` → `novel-queue/data` の `json` フィールド）
3. どちらもなければ保存しない。その旨を画面上部の帯で告げる

`localStorage` / `sessionStorage` は使わない（この道具が置かれる環境で使えない）。
保存はすべて try/catch で囲み、失敗は帯に出す。書き込みは0.7秒まとめてから一度だけ送る。
控えの画面からJSONで書き出し／読み込みができる。バックアップと、環境をまたぐ移動のため。

## 画面

| 画面 | すること |
|---|---|
| いま | 予約の残り日数、仕込み待ち、未検査、次の投稿、次の手 |
| 作品 | 全作品の台帳。状態と「本にする」で絞り込む |
| 分割 | 話に分ける。字数とR-18を入れ、「毎日で割り当て」で日付を振る |
| 予定 | 日付順の一覧。予約に入れ終えた印を押す。↑↓で日付を入れ替える |

「毎日で割り当て」は1日1本。すでに埋まっている日は飛ばして次の空き日に置く。
「日付のない話だけに振る」と「ぜんぶ振り直す」を選べる。

## 運用の前提（迷ったときの背景）

- **投稿時刻は20時より前**に揃える。pixivの同日ランキング集計に乗る条件が20時のため。
  既定は19時。20時以降を選ぶと朱で断る。
- **シリーズ機能**で束ねる前提。作品名がそのままシリーズ名になる。
- **タグの表記ゆれは致命的**（流入の約9割がタグ検索）。話の画面に「よく使うタグ」を
  出現数の多い順に出し、押すだけで足せる。「前の話から写す」もある。
- 交流をしない運用なので、感想返信やフォロー管理は持たない。

## 触るときの約束

- 投稿の自動化を足さない（pixiv・X・いずれも）
- `checked` と `reserved` を混ぜない
- 本文テキストを持たせない
- 数字はひとつだけ大きく、あとは静かに。SaaSのダッシュボードにしない
- 画面の言葉は作者の語彙のまま（仕込み待ち／束／振る／控え）
