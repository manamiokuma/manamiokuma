# 帳場 — 引き継ぎ資料

最終更新：2026年9月8日
対象ファイル：`chouba.html`（単一ファイル・依存ライブラリなし・外部への通信は見出しのフォントだけ）

書いている小説ぜんぶの台帳。**作品**を芯に置いて、三つの流れを一枚で見る。

1. **進捗** — いま何がどの段階まで書けているか（Claudeとの制作工程そのまま）
2. **本** — 同人誌にするもののシリーズと、便（発行）ごとの入稿・頒布の日どり
3. **公開** — pixivに毎日出すぶんの在庫と予約

旧称は「日繰り」（`higuri.html`）。pixivの投稿在庫だけを見る道具だったが、
2026.9.8 に台帳へ広げて改称した。保存キーは `novel-queue:data` のまま引き継いでいる。

## 画面

| 画面 | すること |
|---|---|
| いま | いちばん知りたい数字ひとつ。入稿が近ければ「入稿まであと◯日」、そうでなければ「予約ずみ あと◯日ぶん」 |
| 作品 | 全作品の台帳。段階・種別で絞り込む。押すと進捗と出しかたと話の一覧 |
| 本 | 発行（便）の予定と、シリーズの巻立て |
| 公開 | pixivの日付順。予約に入れ終えた印を押す |

**大きい数字はひとつだけ。** 入稿日が近づく（既定21日）とそちらへ切り替わる。
切り替えの日数は控えの画面で変えられる。

## 段階

`fanfic-production` の制作サイクルをそのまま段階に使う。

構想（段階0）／矛盾検証（段階1）／起稿（段階2）／統合（段階3）／文体改稿（段階4）／
入稿テキスト（段階5）／完成／保留／**未記入**

**「未記入」は推測を入れないための段階。** 正本にどこまで進んだか書かれていない作品は、
それらしい段階を当てずに未記入にしてある。ダッシュボードの「次の手」がこれを拾って、
埋めるよう促す。

## かたち

- **作品（Work）** `title` `fandom` `kind`（未定／pixiv／同人誌／両方）`stage` `chaptersDone/Total`
  `charsNow/Target` `seriesId` `releaseId` `updatedAt` `note` `driveUrl` `driveTitle` `driveModified`
- **話（Episode）** pixivの投稿単位。`checked`（文体検査を通した）と `reserved`（pixivの予約に入れ終えた）は**別の印**
- **シリーズ（Series）** 巻もの。作品側の `seriesId` で結ぶ
- **発行（Release）** 便・イベント。`eventDate`（頒布日）`deadlineAt`（入稿日）`dateNote`（日が決まっていないときの書き置き）`state`

## やらないこと

- **pixivとXへの自動投稿はしない。** 公式APIがなく、非公式の道はcookieとUAを直に扱うことになる。
  8年ぶんの作品が乗っているアカウントで負える賭けではない。投稿は予約投稿機能に手で入れる
- 外部APIへの接続・スクレイピング・自動ログインを足さない
- 原稿の文体検査はしない（`manuscript-qa` の仕事）
- 本文テキストを持たない。分割は話数・字数・タイトル・R-18だけ

## 出しおわった話の登録

**予約する前提だけの作りにしない。**もうpixivに出してある話は、あとから台帳に入れられる。

- 入口は二つ。公開の画面の「pixivに出しおわった話を登録する」と、
  作品の画面の「出しおわった話を登録する」
- 作品を選ぶか、その場で新しい作品として足す（種別はpixiv・段階は完成で入る）
- 入れると **検査ずみ・予約ずみ・公開ずみ**の三つが立つ。日付はさかのぼって入る
- 続けて登録できる。作品と時刻はそのまま残り、**日付だけ一日進む**（連載を順に入れるため）

話の印は三段になった。

| 印 | 意味 |
|---|---|
| `checked` | 文体検査＋目視を通した |
| `reserved` | pixivの予約に入れ終えた |
| `posted` | 実際に世に出た（`postedAt` に日付） |

公開ずみの話は「仕込み待ち」にも「次の手」にも出てこない。すでに終わっているため。

## 原稿から数える

「書けた章／全章／いまの字数」は手で入れなくてよい。**原稿を読ませて数える。**

- **ドライブから** — 作品に結びつけた原稿を読んで数える（`download_file_content`）
- **ファイルを選ぶ** — 端末の `.docx` `.txt` `.md` を選んで数える。docxは朱入れと同じく
  zipを直接ほどいて読む（通信なし・`DecompressionStream("deflate-raw")`）

数えるもの。

| 出すもの | 中身 |
|---|---|
| 字数 | 空白と改行を除いた文字数。台帳に入るのはこれ |
| そのまま | 改行と空白を含めた文字数（参考。並べて出す） |
| 見出し | `第◯章／話／節／部／幕／回`・プロローグ・エピローグ・序章・終章・幕間・間奏 の行数 |

**数えた結果はすぐには入らない。**いちど出して見せ、「この数を入れる」を押して入る。
入るのは字数と全章で、**書けた章は手のまま**（どこまで書けたかは機械には分からない）。

RTF（Macのテキストエディットが吐く `.txt`）も一応ほどけるようにしてあるが、
2026.9 以降はWordで持つ方針。

## ジャンル・CP・AU

一項目だった「ジャンル・CP」を三つに割った。`genre` `cp` `au`。

- 入力欄には、これまでに使った値が候補として出る（表記を揃えるため。タグと同じ考え）
- 作品の画面の上で、三つそれぞれで絞り込める
- 一覧の下に**内訳**が出る。ジャンル別・CP別・AU別の本数と、完成／書きかけの内訳。
  行を押すとその値で絞り込む

旧い `fandom`（「原神／ファルカ×ローエン（狼男×吸血鬼AU）」の形）は、読み込み時に
自動で三つに割る。割り切れなかったぶんは手で直す。

## 表紙

作品にも**話にも**表紙を持てる。pixivは小説一本ずつに表紙を登録できるため、
**見え方の確認**ができることを主にした。

- 画像は長辺900pxほどに縮め、**pixivの表紙枠（600×848）**と**一覧での見え方（正方形）**の
  二つの枠に流して見せる。はみ出したところがどう切れるかがその場で分かる
- 置き場は台帳とは別（`covers/<id>` に一件ずつ）。台帳の控えJSONには入らない
- 大きすぎる画像は、入る大きさになるまで段階的に落とす。それでも入らなければ断る
- 作品一覧・発行の中身・公開の予定に、小さな表紙が並ぶ

## サンプルとURL

同人誌（種別が「同人誌」か「本＋pixiv」）の作品には、**サンプル**の欄が出る。

| 印 | 意味 |
|---|---|
| サンプル未 | まだ何もしていない |
| 用意した | 画像や本文サンプルはできたが、まだ出していない |
| 公開ずみ | 出した（押した日が入る。置き場のURLも持てる） |

**入稿テキストまで進んだ本**だけを「サンプルがまだ」に出す。まだ書いている本を急かさない。
発行の一覧にも「サンプル未 ◯冊」が付き、ダッシュボードの「次の手」も拾う。
サンプル公開は旗艦ポストを再掲するきっかけになる（`book-promotion`）。

pixivのURLは二段で持つ。

- **作品**：シリーズのURL（分割した話はpixivのシリーズにまとめる前提。作品名＝シリーズ名）
- **話**：出したあとの、その話のURL。入っている話は予定の一覧に「出しました」と付く

## ドライブの点検

**ドライブの控えは最新とはかぎらない**（手元で直したぶんが上がっていないことがある）ので、
台帳の側から見に行って突き合わせる。

- 作品の画面の「ドライブを見に行く」で、題（または「探す言葉」）でドライブを検索し、
  見つかったファイルを選んで結びつける。**勝手には結ばない**
- 控えの画面の「ドライブを見に行く（12本ずつ）」で、確かめた日の古い順に12本を見に行く。
  すでに結んである原稿は更新日を取り直し、まだ結んでいないものは候補の有無だけ見る
- 見立て：`updatedAt`（台帳で「今日これを進めた」を押した日）が `driveModified`（ドライブの更新日）
  より新しければ「控えが古いかも」を朱で出す。手で「これが最新」「控えは古い」と印をつければ、
  その印が見立てより優先される

呼び出しは Artifact の `mcp` 機能を通し、**Googleドライブの `search_files` だけ**を宣言してある
（検索のみ。読み書きはしない）。認証は閲覧者のもので、ページはトークンを見ない。
つながっていないときは、エラーの種類ごとに直しかたを出す（つなぎ直し／追加／選択）。

**この機能を宣言しているあいだ、この道具は公開共有ができない**（コネクタの同意を伴うため）。
自分だけで使うぶんには支障はない。

## 保存

`novel-queue:data` ひとつのキーに全体をJSONで入れる。保存先は起動時に上から順に探す。

1. `window.storage`（ホスト環境のキー・バリューストア）
2. Artifactの `db`（`novel-queue/data` の `json` フィールド）
3. どちらもなければ保存しない。その旨を画面上部の帯で告げる

`localStorage` / `sessionStorage` は使わない。保存はすべて try/catch で囲み、
失敗は帯に出す。書き込みは0.7秒まとめて一度だけ送る。控えの画面からJSONで書き出し・読み込み。

**推測で埋めた欄はない。** 正本に書かれていない段階は「未記入」、字数は0のままにしてある。

## 触るときの約束

- 投稿の自動化を足さない
- `checked` と `reserved` を混ぜない
- 段階を推測で埋めない（分からないものは未記入のまま出す）
- 本文テキストを持たせない
- 数字はひとつだけ大きく。SaaSのダッシュボードにしない
- 画面の言葉は作者の語彙のまま（便／仕込み待ち／束／振る／控え）
