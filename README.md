# 朱入れ

同人小説の推敲を、最後まで続けられるようにするための道具。

`shuire.html` を一枚ブラウザで開くだけで動きます。ビルドなし、依存ライブラリなし、通信なし。
本文は端末の中（localStorage）にだけ置かれ、どこにも送られません。

## 何をしてくれるか

**終わりを見せる。** 本文を二千字前後の「区切り」に割って、印刷所の面付けのようなマス目に並べます。
ひと区切り読み終えるたびにマスが朱で埋まる。残りが目で分かるようにするのが第一の仕事です。
章の頭（`第◯章`、`プロローグ`、`＊` など）は字数にかかわらず必ず切れます。

**見るところを一つに絞る。** 通しごとに種類を決めます。

| 通し | 見るところ |
|---|---|
| 誤字と表記 | 字面だけを見る。意味は追いかけない |
| 文体とリズム | 語尾の重なり、文の長さ、読みの息つぎ |
| 話のつじつま | 時系列、呼び方、前に書いたこととの食い違い |
| 通して読むだけ | 直さずに読む。引っかかった行にだけ朱を置く |

**決められないことを、決めずに先へ進む。** 「ここが変だけれど、どう直せばいいか今は分からない」ところには、
ボタン一つで**付箋**を貼れます。行の右にある「朱」「付」を押すだけ。
朱は「直す」と決めた行、付箋は「まだ決まっていない」ところ。控えで付箋だけを集めて見返せるので、
そこで手が止まらずに済みます。付箋は通しをまたいで残り、面付けのマスにも山吹色の角が立ちます。
入稿用のテキストを書き出すときに付箋が残っていれば、その場で数を教えます。

**曖昧なままで構いません。** どこが変か行を指せないときのために、三段構えにしてあります。

| どのくらい分かっているか | やること |
|---|---|
| この一文が変 | その行に付箋 |
| この辺りが変（行までは絞れない） | 続けて何行かに付箋。ひとつづきの相談として扱われます |
| この区切りが何か変（どこかも分からない） | 本文の下の「どこが変か分からない — この区切りごと相談する」 |

付箋を貼ると、その場に**手触りの札**（なんとなく変／重い／説明しすぎ／間が悪い／視点が動く／
声じゃない／言葉が浮く）とひとこと欄が出ます。押すだけ、書かなくても構いません。
言葉になっていない引っかかりを、言葉になっていないまま持ち越せるようにしてあります。

**付箋はそのままClaudeへの相談になる。** どう直すか分からない場所は、相談したい場所でもあります。
作品の画面の「付箋をClaudeに相談する」から**相談票**を写して、Claudeに貼ってください。
付箋のところが、前後二文と手触り、区切りの覚え書きといっしょに `[F1]` の番号付きで並び、
（範囲なら範囲ぜんぶ、まるごとなら区切りの全文が入ります）
何を答えてほしいか（見立てと、文体を保った直しの案を二つ以上）、いまどの通しで読んでいるか、
そして**書き手自身も何が起きているか言葉にできていないことが多いので、決めつけずに
まず言い当ててほしい**ことまで書いてあります。

**Claudeが記憶ではなく正本を見て答えるように、開いてほしいスキルを名指しします。**
相談画面で作品の世界を選んでおくと、票の頭がこうなります。

```
【先に開いてほしいスキル】
・writing-style（文体の正本）
・lukaen-omega-reference（この作品の設定の正本）
・genshin-reference（併せて開く設定の正本）
・r18-craft（R18の様式の正本）
※ このシリーズは原作軸の上に乗っているので、genshin-reference も必ず併せて開いてください。
文体・呼称・口調・世界観の裁定は、記憶ではなく上のスキルに従ってください。
```

併用の可否はスキル側の取り決めどおりです。アムル世界なら `genshin-reference` を
「開かないでください」と書き、『前説』なら `r18-craft` を挙げません。

返ってきた文をまるごと貼り戻せば、番号どおりにそれぞれの付箋へ案が付きます。
案の付いた行には印が出て、押すと候補が並び、選べばそのまま直しの欄に入ります。
**運ぶのは人（写す／ファイル）で、この道具はどこにも通信しません。**

**機械に先に読ませる。** 字面の規則で拾えるものは機械が拾い、あやしい行に薄い線を引きます。
人が置くのが**朱**、まだ決めていないのが**付箋**、機械が引くのが**鉛筆**。色を分けてあります。
うるさい項目は設定で一つずつ消せます（消しても本文は変わりません）。

拾うもの — 三点リーダとダッシュの数、！？のあとの空き、かっこの対応、行頭の字下げ、
半角の記号とカナ、`，．` の混入、**表記のゆれ**（作品ぜんぶを見て少ないほうの表記に線を引く）、
長い一文、読点の多さ、文末の重なり、同じ語のくり返し、かな・漢字の続きすぎ、前の行との重なり、指す言葉の重なり。

**その場で直す。** 行を押すとそこだけ直せます。もとの本文は残るので、
控えに「もとの文 → 直した文」が並び、書き出せばそのまま入稿用のテキストになります。
Wordとの往復が要りません。

**続けられるようにする。** 推敲は嫌になるのが普通なので、続ける側を支えます。

- **きょうの分** … 一日に読めたら上出来という区切り数を決めておきます（既定は三区切り、およそ三十分）。
  一覧に点で残りが出ます。少なめに決めておくのがこつです
- **つづきを読む** … 最後に開いた原稿の、次の区切りへ一押しで入れます。始める手間をなくすため
- **見通し** … 直近二週間の実績から「この調子だと ◯月◯日ごろ（あと◯日）に読み終わります」。
  残量を、日数に変えて見せます
- **校了** … 通し終えたら朱印を押せます。通した記録（何回目・どの見かた・いつ・直した数）が残ります
- **締め切り** … 入稿日を決めると、見通しが逆算に切り替わります（下記）
- **前の通しと比べて** … 傾向表に、前の通しを終えたときの鉛筆の数と今の数が並びます。
  減っていれば、直す手が身についたということ

**締め切りがあるときは、逆算する。** 作品ごとに入稿日を決めると、「この調子だと◯日」ではなく
「間に合わせるには一日いくつ」に変わります。

```
入稿まで あと6日（9月14日）　一日 3 区切り（およそ33分）
いまの調子なら 2日ぶん余ります。
```

一覧の頭には濃い帯が立ち、その日に要る数と進み具合が出ます。押せばそのまま続きへ入ります。
きょうの分も、決めた数ではなく締め切りから逆算した数に切り替わります。
遅れているときだけ、間に合わせる筋道（この通しを最後にして校了へ回す／下読みを誤字だけに絞る）を
一行で添えます。当日は「きょうが締め切り」、過ぎれば帯が変わります。締め切りはいつでも外せます。

**傾向を見せる。** どの種類の指摘が何件残っているか、通しごとに何件直したか。
同じ指摘が減っていけば、直す手が身についたということです。

**消えないようにする。** 作品まるごとを一つのWordに控えます（`作品名_控え.docx`）。
本文は直しを反映し、直した行は緑、朱は赤、付箋は山吹。各区切りの控え（もとの文 → 直した文、
付箋と手触り、朱、覚え書き）も入ります。**端末のデータが消えても、Wordの側に残ります。**

いつ控えるかは三つから選べます。既定は**読む画面を離れるとき**（ひと続きの朱入れが終わるたびに一つ）。
区切りごとにも、押したときだけにもできます。印が一つもないうちは書き出しません。

パソコン（Chrome/Edge）なら、控えの置き場（フォルダ）を一度決めておけば、ダウンロードが増えず
**同じ一つのファイルに上書き**されます。次に開いたときも覚えています。

## 書き出し

| 書き出し | 中身 |
|---|---|
| 直した本文（テキスト） | 入稿用。区切りの印は入らず、原稿の改行のまま |
| 直した本文（Word） | 直した行は緑、朱を置いた行は赤 |
| 控え（Word／テキスト） | 「もとの文 → 直した文」、付箋（届いた案つき）、朱を置いた行、覚え書き |
| 相談票（テキスト） | 付箋の行＋前後二文＋覚え書き。Claudeに渡す紙 |
| もとの本文（テキスト） | 読み込んだときのまま |

## 使いかた

`shuire.html` をブラウザで開く。`.docx` `.txt` `.md` を選ぶか、Wordから本文を貼りつけて「区切って始める」。

iPhoneでも同じように動きます。ファイルアプリから `.docx` を選べます。

## 確かめかた

```bash
node tools/selftest.mjs    # 分割・復元・下読み・docxの読み書き（依存なし）
node tools/uitest.mjs      # 画面の通し（playwright が入っているときだけ）
```

## 触るときの約束

- 通信を足さない（CDN・API・解析ツールすべて）
- 原稿の本文を端末の外に出さない
- 三つの印の意味を混ぜない（朱＝直すと決めた／付箋＝まだ決まっていない／鉛筆＝機械が引いた）
- 濃い背景に戻すなら、背景が効かない場合の見え方を先に確かめる
- 画面の言葉は同人・印刷の語彙のまま（区切り／通し／朱／鉛筆／控え／面付け）

くわしい設計の理由と地図は `docs/引き継ぎ.md` に。
