# 朱入れ — 引き継ぎ資料

最終更新：2026年9月7日
対象ファイル：`shuire.html`（単一ファイル・依存ライブラリなし・通信なし）

---

## 1. これは何か

同人小説の推敲を最後まで続けられるようにするための道具。

作った動機は「量が多くて終わりが見えない」こと。一冊を一本のファイルで開くと進捗がスクロールバーでしか
分からないので、約2,200字の区切りに割って、印刷所の面付けのようなマス目で残量を見えるようにしてある。

**前の版（試作）からの一番大きな変更は、校正そのものをこの道具の中でやるようにしたこと。**
試作では「マークして、あとでWordで直す」だった。それだと結局Wordとの往復が残り、
そこがいちばん面倒だったので、行をその場で直せるようにした。書き出せば入稿用のテキストが出る。

### できること

1. `.docx` / `.txt` / `.md` を読み込み、章の頭と句読点の位置で約2,200字ずつに分割
2. マス目で全体を表示。区切りを読み終えるとマスが朱で埋まる
3. 残り区切り数と推定所要時間（初期値200字/分。設定で変えられる）
4. 本文の一文ずつがボタンになっていて、右の「朱」「付」で印の付け外し、本文を押すとその場で直せる
   （朱＝直すと決めた行／付箋＝どう直すか決まっていない行。控えで付箋だけ集められる）
5. 機械の下読み（鉛筆）。字面の規則で拾える指摘を先に立てておく
6. 通しの種類（誤字／文体／つじつま／通し読み）。種類ごとに出る鉛筆が変わる
7. 区切りごとの覚え書き
8. 控え（直し・朱・覚え書きの一覧）と傾向表
9. 続けるための仕掛け（きょうの分・つづきを読む・見通し・校了・前の通しとの比べ）
10. 付箋をClaudeに相談する（相談票を書き出し、返事を貼り戻して案を付ける）
11. 書き出し五種＋相談票
12. 続いた日数・今日の消化数・累計

## 2. 設計上の決定と、その理由

変更するときは理由のほうを見てから決めてほしい。

- **単一HTML・外部ライブラリなし・通信なし。** 原稿が端末の外に出ないようにするため。
  docxの読み書きも自前で実装してある（後述）。CDNを足すとこの前提が崩れる。
- **紙の白地に藍の文字、朱だけが赤。** 最初は青焼き（印刷所の校正刷り）に寄せた濃紺の地だったが、
  背景色の指定が効かない環境で薄い文字が白地に乗って読めなくなった。
  **背景指定が失われても読める側に倒す**方針。暗い配色に戻すなら、背景が消えた場合の見え方を必ず確認すること。
- **印は三つ。朱＝人が「直す」と決めた行、付箋＝人が引っかかったがどう直すか決まっていない行、
  鉛筆＝機械が引いた線。** 機械の指摘を人の判断と混ぜないために色を分けてある。機械は字面しか
  見ていないので必ず外す。外したときに「機械が間違えた」で済むよう、色で区別する。
  朱と付箋を分けたのは、「変だと分かるが直し方が分からない」ところで手が止まるのを防ぐため。
  そこで悩まずに付箋を貼って先へ進み、あとで控えの「付箋」だけを見て考え直せる。
  だから**付箋は通しをまたいで消えない**し、入稿テキストを書き出すときに残数を知らせる。
  三つの印を他の意味に使わない。
- **通しに種類を持たせた。** 一度に全部を見ようとすると終わらない。誤字の通しでは文体の鉛筆を出さない。
  見るところが減ることが、この道具のいちばんの仕事。
- **直しは原文を残した差分で持つ。** `blocks[i].edits` は「原文の行番号 → 直した文」の疎な辞書。
  原文 `blocks[i].t` は書き換えない。だから行番号がずれず、控えに「もと → 直し」が出せて、
  いつでも元に戻せる。**ここが壊れると全部壊れるので、原文を直接書き換える実装にはしないこと。**
- **区切りは本文の切れ端そのもの。** `blocks` の `t` をそのまま順につなぐと、必ず元の本文に戻る
  （`workText()` が `join("")` なのはそのため）。改行や空行が一つでも落ちると入稿テキストが狂うので、
  ここは `tools/selftest.mjs` で常に確かめている。
- **区切りは字数で割る（章ではなく）。ただし章の頭では必ず切る。** 一区切りがスマホで10〜15分に
  収まることを優先。章単位にすると長さが揃わず、終わりの見えなさが戻る。
- **続ける仕掛けは、静かに。** 点数・記章・演出で煽らない。効くのは
  「始める手間を減らす」「終わりが日付で見える」「積み上がりが記録に残る」の三つだと踏んでいる。
  祝うのは校了の朱印だけ。朱は校正の色なので、校了印に使うのは筋が通っている
  （それ以外の飾りに朱を使わない）。
- **語彙。** 画面の言葉は同人・印刷の語彙で統一（区切り／通し／朱／鉛筆／控え／面付け）。
  「タスク」「アイテム」「完了」は使わない。

## 3. データ

`localStorage` に保存している。書き込みに失敗したときは、その回だけメモリ（`mem`）で動き続ける。

| キー | 中身 |
|---|---|
| `shuire:index` | 作品一覧 `[{id, title, done, total, pass, kind}]` |
| `shuire:work:<id>` | 作品本体（下記） |
| `shuire:daily` | `{"2026-09-07": 3, ...}` 日付ごとの消化区切り数 |
| `shuire:conf` | 設定 `{rules:{規則id:bool}, pen:false, mine:true, cpm:200, wordWhen:"leave", quota:3, last:id, sync:false, at}` |
| `shuire:memory` | 過去の直しの持ち越し `[{o, n, w:作品名, at, memo?:true, c?:回数}]`。上限4000件 |
| IndexedDB `shuire/kv/dir` | 控えの置き場（フォルダの取っ手） |

作品本体：

```js
{
  v: 2,
  id, title, created, size,
  blocks: [{
    t:     "区切りの本文（原文のまま。書き換えない）",
    done:  false,           // この通しで読み終えたか
    note:  "",              // 区切りごとの覚え書き
    marks: [0, 4],          // 朱を置いた行番号（直すと決めた）
    fusen: [7, 8],          // 付箋を貼った行番号（続き番号はひとつづきの相談になる）
    ftags: {8: ["重い","間が悪い"]},  // 付箋の手触りの札
    fmemo: {8: "台詞のあと、間が足りない"},  // 付箋のひとこと（読点を打てる）
    wide:  {on:false, memo:"", tags:[]},     // 区切りまるごとの付箋（どこが変か行を指せないとき）
    advice:{7: "見立て：…\n案：…", all: "…"},  // 取り込んだ返事（行番号ごと。all はまるごと）
    edits: {2: "直した文"},  // 行番号 → 直した文（疎）
    head:  true             // 章の頭で始まる区切りか
  }],
  pass: 2,                  // 何回目の通しか
  kind: "style",            // 通しの種類（typo / style / logic / read）
  log:  [{p, k, b, i, o, n, at, auto?}],   // 直しの履歴。差分回収と先回りの鉛筆の材料。消さないこと。
                                            // auto は機械がまとめて当てた分（癖としては数えない）
  talk: {at, keys: [[区切り, 行], ...]},  // 相談票を出したときの [F番号] の対応
  due: "2026-09-14",        // 入稿日（締め切り）。null なら締め切りモードでない
  closed: false,            // 校了したか。closedAt は校了した日
  history: [{n, kind, finished, marks, fixes, pens, by}],  // 通した記録。pens はその時点の鉛筆の数
  world: "lukaen-omega",    // 作品の世界（WORLDS の id）。相談票に書くスキルが決まる
  r18: true,                // R18を含むか（既定は true）
  moreSkills: "",           // そのほかに開いてほしいスキル（書き手の自由記入）

  history: [{n, kind, finished, marks, fixes}]
}
```

行番号は `lines()` が返す配列の添字。`lines()` の分割規則を変えると既存データの行番号がずれるので、
**変えるなら移行処理が要る。** `migrate()` に旧v1（`blocks` が文字列の配列だった頃）からの移行が入っている。

`marks` `fusen` `edits` の行番号がどれも原文に対して付いているので、直しを何度入れても番号はずれない。
「区切りを割り直す」だけは番号が壊れるので、直しを本文に溶かし込んでから割り直し、朱・付箋・覚え書きは捨てている
（捨てる前に確認を出している）。

## 4. コードの地図

`shuire.html` 一枚。上から `<style>` → 画面十個の `<section>` → `<script>`。
画面は `view("home"|"work"|"read"|"notes"|"report"|"out"|"add"|"pass"|"conf"|"about")` で切り替える
（該当セクション以外に `.hide` を付けるだけ）。

### 保存
`jget` / `jset` / `jdel` — localStorageの読み書き。失敗しても落ちない
`saveWork(now)` — 作品の保存。既定は0.5秒まとめ書き、`now` で即時
`flushWork()` — 作品と一覧の両方を書く（画面を離れるときに呼ぶ）

### 本文を割る
`isHead(p)` / `sections(t)` — 章の頭を見つけて、そこで切る。**切れ端をつなぐと元の本文に戻る**のが約束
`splitSize(text, size)` — 指定字数の手前から後ろ向きに `\n` `。` `」` を探して切る
`cutBlocks(text, size)` — 上の二つを合わせて `blocks` を作る
`lines(text)` — 一区切りを一文ずつに割る。段落の境目には `null` を入れ、表示側で余白にしている
`lineText(b, ls, k)` / `blockText(b)` / `workText(w)` — 直しを当てはめた表示・書き出し用の本文

### 下読み（機械の鉛筆）——**既定で止めてある**
書き手の言葉：「鉛筆はあまり役に立ってないかも」。字面の規則（誤字と表記の衛生）は、同人誌を
何冊も出している人の困りごとではなかった。`conf.pen` が元栓で既定 false。`readBlock` は
`conf.pen===true` のときだけ `RULES` を使う（`mineCache`＝自分の直しから作る鉛筆は別栓 `conf.mine`）。
消さずに残してあるのは、表記のゆれだけ見たい日があるかもしれないから。**既定を戻さないこと。**
`RULES` — 規則の配列。`{id, cat, name, desc, f(s, ctx), para?}`
  `cat` は `hyoki` / `buntai` / `seigou` の三つ。通しの種類がこれで絞り込む
  `para:true` の規則は一文ではなく段落全体を見る（かっこの対応がこれ。会話文の中の句点で文が割れるため）
`readBlock(b, cats)` — 一区切りぶんの下読み。`{行番号: [{id, msg}]}` を返す
`YURE` / `buildYure(w)` — 表記のゆれ。作品ぜんぶを見て、漢字とかなの両方が使われている語を探し、
  **少ないほうの表記に鉛筆を引く**（多いほうに揃えるのが自然なので）。40件を超えたら諦める
`tailOf(s)` — 地の文の文末一字。会話（〜」）は数えない

規則を足すときは `RULES` に一つ足すだけでいい。設定画面と傾向表は `RULES` から自動で作られる。
足したら `tools/selftest.mjs` に、拾ってほしい文と**拾ってほしくない文**を一組ずつ足すこと。
誤検出は「うるさいから消す」に直結し、消された規則は無いのと同じになる。

### Wordへの控え（消えないようにする仕掛け）
`blockParas(i)` — 一区切りぶんの段落。本文（直し反映・色分け）と、その区切りの控え
`wholeDocx()` — 作品まるごと。**控えはいつも一つのファイル**（`作品名_控え.docx`）にする。
  区切りごとに別ファイルを出すと、一冊読むだけで十数個できて使いものにならない
`wordSnapshot(force)` — 控えを取る。`conf.wordWhen`（leave／each／manual）で頻度が決まる。
  印が一つもない作品では取らない。`cur.wordAt` / `cur.wordDone` で「控え済みかどうか」を見る。
  **非同期なので、書き終えてから `renderWork()` をやり直すこと**（先に描くと古い様子が出る）
`writeOut(bytes,name)` — 置き場（`outDir`）があればそこへ上書き、無ければダウンロード
`pickDir()` / `loadDir()` / `dirOk()` — フォルダの取っ手はIndexedDBに覚える。
  読み込み直したあとは権限が切れているので、`dirOk()` が書き込みの直前に requestPermission する。
  **書き込みは必ず人の操作（クリック）の中で起きるので許可を出せる**——ここを外すと黙って失敗する

localStorage は消えるときは黙って消える。**この控えが唯一の外向きの記録なので、
既定で取ること・止められること・増えすぎないことの三つを守ること。**

### Claudeへの相談
`WORLDS` — 作品の世界と、そのとき開いてほしいスキルの対応表。`skills` は開くもの、
  `note` は書き添える但し書き（「genshin-reference は開かないでください」など）、
  `noR18:true` はR18の存在しない世界。**これはスキル側の取り決めの写しなので、
  スキルの併用ルールを変えたらこの表も直すこと。**放っておくとずれる
`talkSkills()` — writing-style（つねに）＋世界の正本＋R18の様式＋書き手が足したもの
`blockItems(b,i)` / `talkItems()` — **相談の単位**。これが `[F1]` `[F2]` … の番号になる。
  行番号が続いている付箋はひとつの範囲にまとめ、`wide.on` は `a:-1`（まるごと）として先頭に置く。
  段落の境には本文のない行番号が入るので、段落をまたぐ付箋は自然に別の相談になる
`TOUCH` / `memoRow` / `syncMemoRow` — 手触りの札。**札は範囲の終わりの行に一度だけ出す。**
  札（`ftags`）とひとこと（`fmemo`）は**別々に持つ**。一本の文字列に読点でつないでいた頃は、
  ひとことに読点を打てず、打つと札と取り違えていた。`memoOf` / `memoText` が読み書きの窓口。
  ひとこと欄の Enter は、**かな漢字変換の最中は横取りしない**
  （`compositionstart/end`・`isComposing`・`keyCode===229` の三重で見る）。
  日本語で使う入力欄に Enter の手当てを足すときは、必ずこの見張りを付けること
  貼った瞬間の描き直し（`syncMemoRow`）と、開いたときの描画（`openBlock`）で規則を揃えること。
  片方だけ直すと範囲の途中にも札が出る
`talkText()` — 相談票を組む。行・前後二文（`ctxLines`）・区切りの覚え書き・返事の書式の指定。
  **出すたびに `cur.talk.keys` に番号の対応を控える。** そうしないと、書き出したあとに付箋を
  足したり外したりされると、返事が別の行に配られてしまう
`importAdvice(raw)` — 返事から `[F1]`（`［Ｆ１］` も可）を拾い、次の番号までを本文として
  `blocks[i].advice[行]` に入れる。番号の対応は `cur.talk.keys` を優先し、無ければ現在の付箋順
`advCands(text)` — 返事のなかの「案：〜」を押せる候補として取り出す。
  **「：」のうしろの全角空白は落とさない**（行頭の字下げが消えるため）
`advBlock(text)` — シートに出す案の札

相談は写して運ぶだけで、通信は一切しない。Claudeに渡すかどうかは書き手が決める。

### 差分回収と、自分の直しから作る鉛筆（この道具の本当の仕事）
書き手の言葉：「校正ツールというより、わたしの日本語らしくない部分を修正するためのツール」
「manuscript-qa で確認しても、まだ変なところを直してる」。
つまり汎用の禁則（あちらで済んでいる）を二度拾っても意味がなく、**規則になっていない直し**が本題。
朱入れは行を直すたびに `log` に「もと→直し」の対を持っているので、それを材料にする。

`diffRuns(a,b)` — 文字単位のLCS。**消した・足した部分は右へ寄せる**（`slideRuns`）。
  寄せないと「言わなかったのだった→言わなかった」が「ったのだ」と切り出される
`diffMoves(a,b)` — 一組の対を型に割る。sub（言い換え）／tail（文末三字以内＝語尾）／del（削り）／
  add（足し）／punct（読点・記号だけ）／rewrite（十二字超）。punct と add は**本人の領分で規則にしない**
  （manuscript-qa ③の四・七と同じ裁定）。rewrite は規則にしない
`harvest()` / `harvestRows(h,min)` — 全部の対を集計。頻度二以上を規則候補（③の `--min-count` 既定と同じ）
`buildMine()` / `mineCache` — 規則候補から鉛筆を作る。一字のものは拾わない。語尾の鉛筆は
  **語尾（句点の手前三字）にだけ**引く。`readBlock` は通しの種類にかかわらず `mineCache` を混ぜる。
  直しが入るたび（`afterFix`）と開いたとき（`openWork`）に作り直す
`harvestText()` — 回収の書き出し。「差分回収に渡す二本」は `origText` と `workText` の対
`harvest` の `src` — 規則候補ごとに「どの作品で何回」。この作品の `log` は `cur.title`、持ち越しは `w`
`ruleHits(row)` / `applyRule(row)` — **あらかじめ直す**。語句を含む行にまとめて直しを入れる。
  **語尾（tail）と一字は当てない**（活用が絡む／当たりすぎる）。当てた行は `edits` に入り、
  `log` には `auto:true` を付けて積む。**`harvest` は `auto` を数えない**——当てた分を癖として
  数えると、自分で自分を育ててしまう
`moveKind(m)` / `TREND` / `trendRows(h)` — **種類でみた傾向**。同じ文字列の一致は実際には稀なので、
  直しを種類（adv 副詞／subj 主語・代名詞／conj つなぎ／simile 直喩／mind 心理の名指し／
  tailform 説明の語尾／open・close 漢字の開閉／tail・particle・phrase・swap・punct・add・rewrite）に
  分けて数える。分類は語の形の見立て（`ADV` の表と、〜と／〜く／〜かに の形）。「窓に」を副詞に
  取らないよう「〜に」は表にあるものと〜かに・〜やかに だけ。
  **`TREND_MIN`（三回）以上の種類は、`pen` のあるものについて、その種類に属する語が一回きりでも
  鉛筆になる**（`buildMine` の後半）。同じ直しの鉛筆と重なるときは同じ直しの名前が先（`seen`）。
  当てる（applyRule）は傾向からは作らない——種類の語をまとめて当てるのは当たりすぎる
`carryText()` — **執筆に持っていく**。傾向（三回以上）と同じ直し（二回以上）の両方を載せる。二回以上そろった癖を出自（作品名・日付・件数）つきで一枚に。
  manuscript-qa の「出自タグ付きでしか正本へ追記しない」に合わせて、出自を必ず付ける
`sentencesOf` / `alignPairs(A,B)` / `importPairs` — **過去の直しの持ち越し**。二つの版を文の単位で
  突き合わせる。両方に一度きり現れる文を錨にし（patience diff）、錨の間は似た文どうしで組む。
  組むときは似ている度合いに**文の頭が同じぶんを上乗せ**する（短い文どうしだと語尾が同じだけで
  組んでしまうため）。`memory` に作品名つきで貯め、同じ作品を入れ直したら置き換える。
  `allEdits()`＝この作品の `log` ＋ `memory` が、回収と先回りの鉛筆の材料
`parseMemo(text)` / `importMemo` — **差分メモ**の読み込み（初稿が残っていないとき用）。
  一行に一つ、「A → B」（矢印は → ⇒ ➝ -> =>）か「A を削除」「A（削除）」。かっこは剥がす。
  末尾の「3件」「×3」「（3）」は回数。箇条書きの頭と見出し行は落とす。読めない行は `skipped` で返し、
  画面に数と例を出す（黙って捨てない）。メモの対は `memo:true` を付けて貯め、**`harvest` は
  突き合わせずに書いてあるとおりに数える**——「のだった → だった」を文字で突き合わせると
  「の」に縮んで一字除外に落ちるため

**感覚的な直しの大半は規則にならない。それでよい。**この回収は感覚に混じっている「実は型だったもの」
だけを取り出す。誤検出を出さない側（頻度二以上・十二字以内・読点除外・一字除外）に倒してある。
効き目は実際の直しで確かめるしかない。

### 続けるための仕掛け
`pace()` / `eta(rest)` — 一日あたりの区切り数と、読み終わる日の見積もり。
  **十四日で割ると初日は必ず絶望的な数字が出る**ので、実績のある期間（読みはじめた日から今日まで）
  で割っている。実績がなければ何も出さない（当てずっぽうの日付を出さないこと）
`daysTo(due)` / `dueInfo(w)` / `needToday()` — 締め切りモード。`need` は残り÷残り日数の切り上げ、
  当日と超過は残り全部。読み終えた原稿と校了した原稿は急かさない
`renderDue()` / `setDue(v)` — 作品ごとの入稿日。`index` にも `due` を写して、一覧が本文を読まずに
  帯を出せるようにしている（`flushWork` で同期）
`todayNeed()` — 締め切りのある原稿があればその逆算、なければ `conf.quota`
`quota()` / `quotaLeft()` / `renderQuota()` — きょうの分。既定三区切り
`renderResume()` — 最後に開いた原稿（`conf.last`）を一押しで続きから開く。
  **`conf.last` は openWork と原稿の追加の両方で更新する**（片方だけだと出ない）
`passRecord()` / `renderLog()` — 通した記録。`allPens()` でその時点の鉛筆の数も残すので、
  傾向表で前の通しと比べられる
`btn-close` — 校了。朱印を押す。取り消すと、そのとき積んだ記録（`by:"close"`）も取り下げる

### 画面の留まり
`view(v,keep)` / `anchorGet(key)` / `anchorPut(a)` — 手を入れた行を、画面の同じ高さに留める。
  `openBlock(i,keep)` に行番号（まるごとは `"wide"`）を渡すと、描き直しても目が動かない。
  **区切りを描き直す道を足したら、必ずこの錨を渡すこと。**渡し忘れると区切りの先頭に飛ぶ

### 印と直し
`toggleMark(k)` / `toggleFusen(k)` — 朱と付箋。どちらも一タップ。画面は class の付け外しだけで作り直さない
`noteRows()` — 控えの行を組む。直し・付箋・朱・覚え書きを区切り順に並べる。控えの絞り込みと
書き出し（Word／テキスト）は全部これを見ているので、印を足すときはここに一種類足せば全部に載る
`openSheet(k)` / `applyFix()` — 行を直すシート。`edits` に入れて `log` に積む
`afterFix()` — 表記のゆれと鉛筆を引き直して、画面を作り直す

### docxを読む
`readDocx(arrayBuffer)` — zipの中央ディレクトリを自前で走査して `word/document.xml` を取り出す。
圧縮は `DecompressionStream("deflate-raw")` で展開（ライブラリ不要）
`xmlToText(xml)` — `</w:p>` で段落に割り、`<w:t>` の中身を連結。書式・ルビ・注釈は落ちる

### docxを書く
`crc32` / `zipStore(files)` — zipを無圧縮（method 0）で組む。Wordは無圧縮のzipもそのまま開く
`para(runs, head)` — 段落一つ分のXML。`{t:本文, color:"C00000", b:true, st:true, sz:21}` の配列を渡す。
`sz` はハーフポイント（21 = 10.5pt）
`buildDocx(paras)` — 四つのパートをzipに詰める。最小構成なのでスタイル定義は持っていない。
見出しスタイルや目次を入れるなら `word/styles.xml` を足す必要がある
`outText` / `outDocx` / `outNoteDocx` / `outNoteText` / `outOrig` — 書き出し五種

## 4の二. iPhone から使う（claude.ai の非公開ページとして公開する）

iPhone の Safari はローカルの HTML のスクリプトを走らせないので、URL で開ける場所に置く。
この会話の Artifact ツールで非公開ページとして公開してある。
**公開先：https://claude.ai/code/artifact/b3adea04-57cb-4247-8307-68abcf3b969e**（非公開・持ち主だけ）
再公開は、同じ URL を `url` に渡して `node tools/build-artifact.mjs` の出力を publish する。

枠の中で効かないものが二つあり、両方とも本体で手当てしてある。

- **ダウンロード**：`a.download` は枠の中で無効。`save()` は起動時に `claude.use("downloads")` を温めておき
  （`warmHost`）、あれば `downloads.save({filename,data})` に頼む。閲覧者に確認が出て、断られると
  `declined` で戻る。無ければ（ファイルを直接開いたとき）いつもの `a.download`。
  publish するときは `capabilities: {downloads: true, db: {}}` を必ず付ける（`db` は 4の三）。付け忘れると保存が黙って効かない
- **確認の小窓**：`confirm`/`prompt` は枠の中で出ない。`ask(msg,{ok,no,input,numeric,value})` が
  画面の中の小窓（veil/card）で同じことをする。Promise を返すので呼ぶ側は `await`。
  小窓の外を押すか Esc で閉じると null（＝やめる）。**標準の小窓を新しく使わないこと**

iPhone のファイル選択で三つ、手当てしてある。
- `accept` は拡張子だけだと iOS の Files がぜんぶ灰色にすることがあるので、MIME も並べる
- 隠した `<input type=file>` を `.click()` で開かせず、本物の input をボタンの上に透明に重ねる（`.pickwrap`）。
  画面の通し点検は、ボタンの座標を押して選択窓が開くことを見る
- docx の中身をほどく `DecompressionStream("deflate-raw")` は iOS 17 までの Safari にないので、
  失敗したら手書きの `inflateRaw`（RFC 1951）でほどく。`selftest` が Node の zlib と突き合わせる

**枠の中で保存を許されないことがある。** ブラウザが「サイトデータをブロック」（Chrome の第三者クッキー拒否、
Safari の設定、シークレット窓）だと、枠の中のページは `localStorage` に触れただけで例外になる。
起動時に `storeOk` を一度だけ調べ、だめなら (1) 一覧の頭に断り（`renderWarn`）、(2) 「区切って始める」は
保存に失敗しても進む（記憶 `mem` にある）、(3) 枠の中なら `resumeFromStore`：保管庫に原稿があれば黙って揃え、
なければ小窓で保管庫に置くか尋ねる。**起動時の描画から読む状態（`syncOn` など）は先頭で宣言しておくこと**——
`const`/`let` の宣言より前に `renderHome` が走ると TDZ で起動ごと死に、どの端末でも「何も押せない」になる
（一度やった）。`tools/selftest.mjs` の「保存を許されていないブラウザ」が `makeCtx({noStore:true})` で通す。

**この一枚を取り出す。** 公開用の一枚には `build-artifact.mjs` が `shuire.html` を deflate＋base64 で
`<script type="text/plain" id="self-src">` に埋める。「この道具について」の「ファイルとして保存」が
`selfSource()`（`inflateRaw`）でほどいて `save()` に渡す。ファイルで開いた版には埋まっていないので札は出ない。

**自分の置き場（GitHub Pages）。** `shuire.webmanifest` `shuire-sw.js` `shuire-icon.png` を同じ場所に置くと、
iPhone の「ホーム画面に追加」で standalone のアプリになり、圏外でも開く（まず通信、だめなら写し）。
控え係の登録は https かつ枠の外（`window.top===window`）のときだけ。枠の中では `<link rel=manifest>` も外す。

`build-artifact.mjs` は `<!DOCTYPE>` `<html>` `<head>` `<body>` `<meta>` を外すだけ。
`<title>` と `<style>` は頭に残す（枠が最初の 8KB から題名を読む）。

## 4の三. iPhone と PC で揃える（claude.ai の保管庫）と、ファイルで運ぶ

同じ非公開ページを iPhone と PC で開いたとき、原稿・朱・付箋・直し・持ち越しを同じにする。
二本の道があり、**既定はどちらも使わない**（原稿は端末の中だけ、という約束のため）。

### 保管庫で揃える（`conf.sync`、設定画面「claude.ai の保管庫に置いて揃える」）

- 置き場は Artifact の `db` 能力（ページごとの書類置き場。持ち主のアカウントだけに見える）。
  **publish するときは `capabilities: {downloads: true, db: {}}` を必ず付ける**。`db` を落とすと
  `claude.use("db")` が null になり、切り替えは点くが揃わない
- 点けるのは人。点けるとき小窓で「端末の外に置かれる／ページを共有しない」と断る。
  `conf.sync` 自体は揃えない（片方で点けたら両方で点く、にはしない）。`conf.last` も運ばない
- 書類の形（`sync` 節、`shuire.html` の「iPhone と PC で揃える」の下）

  | 書類 | 中身 |
  |---|---|
  | `works/<id>` | 表紙。`WORK_META` の項目＋ `nb`（区切り数）＋ `nl`（履歴の束数）＋ `rev` ＋ `at` |
  | `works/<id>/blocks/<i>` | 区切り一つ（`bodyOfBlock`）＋ `at` |
  | `works/<id>/log/<k>` | 直しの履歴を 400 件ずつ束ねたもの `{items}` |
  | `settings/conf` `settings/daily` | 設定と、日ごとの消化数 `{d}` |
  | `memory/<k>` | 持ち越しを 400 件ずつ束ねたもの `{items}` |

- **勝ち負けは書類ごと、`at` の新しいほう。** `at` は押した時刻ではなく直した時刻（`stampWork` が
  区切りと表紙に付ける。`setDoc` はそれを持っていき、中身が変わったのに印が古いときだけ「いま」にする）。
  直しの履歴と持ち越しは足し合わせる（`unionLog` `unionMemory`）。日ごとの数は多いほう
- **置く順番：区切りと履歴を先、表紙を最後。** 相手は `works` の変化を合図に読みに来るので、
  表紙が先だと古い区切りを読む。表紙は区切りだけ変わったときも `force` で置き直す（合図のため）。
  自分が置いた表紙は `rev` で見分けて読み飛ばす
- 流れ：`jset` → `syncSchedule`（1.5 秒待ち）→ `syncFlush` → `pushWork`／`setDoc`。
  受け取りは `subscribeAll`（`works` 集合、`settings/conf`、`settings/daily`、`memory`）→ `pullWork`。
  点けた直後は `startSync`：先に全部読み（`pullSettings` `pullAll`）、次に手元を全部置き、それから購読
- 消すのは `syncDeleteWork`（表紙・区切り・履歴）。相手は `removed` を見て手元からも外す。
  開いている原稿なら一覧へ戻す
- 受け取って書き戻すときは `quiet()` で `jset` を包む（送り返しの輪を作らない）

### ファイルで運ぶ（通信なし。設定画面「持ち出す／持ち込む」）

`bundle()` が一枚の JSON（`{kind:"shuire", v, at, conf, daily, memory, works}`）。`importBundle` は
原稿ごとに `at` の新しいほうを取り、持ち越しは足し合わせ、日ごとの数は多いほう。
`kind` が違えば断る。AirDrop や iCloud Drive で運べる。

点検は `tools/selftest.mjs` の「iPhone と PC で揃える（偽の保管庫）」。偽の `db`（`fakeDb`）を二つの
端末（`makeCtx()` を二つ）で共有して、置く・降りる・合わさる・あとの直しが残る・消える・切る を通す。

## 7. 触るときの約束

- 通信を足さない（CDN・API・解析ツールすべて）。Claudeへの相談も、運ぶのは人
- 原稿の本文を端末の外に出さない。外へ出すかどうかは、そのつど書き手が決める。
  唯一の例外が「保管庫に置いて揃える」で、これは人が点けたときだけ。既定で点けない。
  点けるときの断り文を弱めない
- 原文 `blocks[i].t` を書き換えない。直しは `edits` に置く。取り込んだ案も、
  人が押すまで本文に入れない
- 区切りをつなぐと元の本文に戻る、を壊さない
- 三つの印の意味を混ぜない（朱＝直すと決めた／付箋＝まだ決まっていない／鉛筆＝機械が引いた）
- 付箋は一タップで貼れること。手触りも札を押すだけで済むこと。
  書かないと進めない作りにしない（言葉にできないから付箋を貼っている）
- 読んでいる場所から目を離させない。行を直したら、その行はその場に留める
- 続ける仕掛けは静かに。点数や記章を増やさない。朱印は校了だけ
- 締め切りで責めない。遅れは事実として出し、間に合わせる筋道を添える
- 機械の下読みは既定で止めたまま。汎用の禁則を増やさない。この道具の仕事は、書き手自身の直しから型を拾うこと。
- 傾向の種類を足すときは `moveKind` に見立てを一つ足し、`TREND` に名前と `pen` を足す。
  分類の見立ては `tools/selftest.mjs` の「削った語を種類に分ける」に、拾ってほしい語と
  取り違えてほしくない語（「窓に」）を一組ずつ足すこと
- 機械が本文に手を入れるのは「当てる」を押したときだけ。黙って直さない。語尾と一字は当てない。
  当てた行は必ず一行ずつ戻せる形で残す
  `log` の対は消さない。規則候補の閾値（二回・十二字・一字除外）は、誤検出を出さない側に倒したまま
- 端末から消えても失われないようにする。Wordの控えを既定で切らない。
  ただし控えは一つのファイルに上書きする。ファイルを増やして使いにくくしない
- 濃い背景に戻すなら、背景が効かない場合の見え方を先に確かめる
- 画面の言葉は同人・印刷の語彙のまま
