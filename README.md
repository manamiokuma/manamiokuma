# 朱入れ

同人小説の推敲を、最後まで続けられるようにするための道具。

`shuire.html` を一枚ブラウザで開くだけで動きます。ビルドなし、依存ライブラリなし、通信なし。
本文は端末の中（localStorage）にだけ置かれ、どこにも送られません。

## 何をしてくれるか

**終わりを見せる。** 本文を二千字前後の「区切り」に割って、印刷所の面付けのようなマス目に並べます。
ひと区切り読み終えるたびにマスが朱で埋まる。残りが目で分かるようにするのが第一の仕事です。
章の頭（`第◯章`、`プロローグ`、`＊` など）は字数にかかわらず必ず切れます。

**見るところを一つに絞る。** 通しごとに種類を決めます。

| 通し | 見るところ |
|---|---|
| 誤字と表記 | 字面だけを見る。意味は追いかけない |
| 文体とリズム | 語尾の重なり、文の長さ、読みの息つぎ |
| 話のつじつま | 時系列、呼び方、前に書いたこととの食い違い |
| 通して読むだけ | 直さずに読む。引っかかった行にだけ朱を置く |

**決められないことを、決めずに先へ進む。** 「ここが変だけれど、どう直せばいいか今は分からない」ところには、
ボタン一つで**付箋**を貼れます。行の右にある「朱」「付」を押すだけ。
朱は「直す」と決めた行、付箋は「まだ決まっていない」ところ。控えで付箋だけを集めて見返せるので、
そこで手が止まらずに済みます。付箋は通しをまたいで残り、面付けのマスにも山吹色の角が立ちます。
入稿用のテキストを書き出すときに付箋が残っていれば、その場で数を教えます。

**曖昧なままで構いません。** どこが変か行を指せないときのために、三段構えにしてあります。

| どのくらい分かっているか | やること |
|---|---|
| この一文が変 | その行に付箋 |
| この辺りが変（行までは絞れない） | 続けて何行かに付箋。ひとつづきの相談として扱われます |
| この区切りが何か変（どこかも分からない） | 本文の下の「どこが変か分からない — この区切りごと相談する」 |

付箋を貼ると、その場に**手触りの札**（なんとなく変／重い／説明しすぎ／間が悪い／視点が動く／
声じゃない／言葉が浮く）とひとこと欄が出ます。押すだけ、書かなくても構いません。
言葉になっていない引っかかりを、言葉になっていないまま持ち越せるようにしてあります。

**付箋はそのままClaudeへの相談になる。** どう直すか分からない場所は、相談したい場所でもあります。
作品の画面の「付箋をClaudeに相談する」から**相談票**を写して、Claudeに貼ってください。
付箋のところが、前後二文と手触り、区切りの覚え書きといっしょに `[F1]` の番号付きで並び、
（範囲なら範囲ぜんぶ、まるごとなら区切りの全文が入ります）
何を答えてほしいか（見立てと、文体を保った直しの案を二つ以上）、いまどの通しで読んでいるか、
そして**書き手自身も何が起きているか言葉にできていないことが多いので、決めつけずに
まず言い当ててほしい**ことまで書いてあります。

**Claudeが記憶ではなく正本を見て答えるように、開いてほしいスキルを名指しします。**
相談画面で作品の世界を選んでおくと、票の頭がこうなります。

```
【先に開いてほしいスキル】
・writing-style（文体の正本）
・lukaen-omega-reference（この作品の設定の正本）
・genshin-reference（併せて開く設定の正本）
・r18-craft（R18の様式の正本）
※ このシリーズは原作軸の上に乗っているので、genshin-reference も必ず併せて開いてください。
文体・呼称・口調・世界観の裁定は、記憶ではなく上のスキルに従ってください。
```

併用の可否はスキル側の取り決めどおりです。アムル世界なら `genshin-reference` を
「開かないでください」と書き、『前説』なら `r18-craft` を挙げません。

返ってきた文をまるごと貼り戻せば、番号どおりにそれぞれの付箋へ案が付きます。
案の付いた行には印が出て、押すと候補が並び、選べばそのまま直しの欄に入ります。
**運ぶのは人（写す／ファイル）で、この道具はどこにも通信しません。**

**機械の下読みは、ふだん止めてあります。** 三点リーダの数、かっこの対応、表記のゆれといった
字面の規則で鉛筆を引く仕組みは残してありますが、既定では出ません。書き手の言葉——
「鉛筆はあまり役に立ってないかも」。誤字と表記の衛生は、この道具の仕事ではありませんでした。
見たい項目がある日だけ、設定の「機械の下読みを使う」を点けて、項目を選んでください。
人が置くのが**朱**、まだ決めていないのが**付箋**、機械が引くのが**鉛筆**。色を分けてあります。

**その場で直す。** 行を押すとそこだけ直せます。もとの本文は残るので、
控えに「もとの文 → 直した文」が並び、書き出せばそのまま入稿用のテキストになります。
Wordとの往復が要りません。

**続けられるようにする。** 推敲は嫌になるのが普通なので、続ける側を支えます。

- **きょうの分** … 一日に読めたら上出来という区切り数を決めておきます（既定は三区切り、およそ三十分）。
  一覧に点で残りが出ます。少なめに決めておくのがこつです
- **つづきを読む** … 最後に開いた原稿の、次の区切りへ一押しで入れます。始める手間をなくすため
- **見通し** … 直近二週間の実績から「この調子だと ◯月◯日ごろ（あと◯日）に読み終わります」。
  残量を、日数に変えて見せます
- **校了** … 通し終えたら朱印を押せます。通した記録（何回目・どの見かた・いつ・直した数）が残ります
- **締め切り** … 入稿日を決めると、見通しが逆算に切り替わります（下記）
- **前の通しと比べて** … 傾向表に、前の通しを終えたときの鉛筆の数と今の数が並びます。
  減っていれば、直す手が身についたということ

**締め切りがあるときは、逆算する。** 作品ごとに入稿日を決めると、「この調子だと◯日」ではなく
「間に合わせるには一日いくつ」に変わります。

```
入稿まで あと6日（9月14日）　一日 3 区切り（およそ33分）
いまの調子なら 2日ぶん余ります。
```

一覧の頭には濃い帯が立ち、その日に要る数と進み具合が出ます。押せばそのまま続きへ入ります。
きょうの分も、決めた数ではなく締め切りから逆算した数に切り替わります。
遅れているときだけ、間に合わせる筋道（この通しを最後にして校了へ回す／下読みを誤字だけに絞る）を
一行で添えます。当日は「きょうが締め切り」、過ぎれば帯が変わります。締め切りはいつでも外せます。

**自分の直しから、規則を育てる。** この道具の本当の仕事はここです。
`manuscript-qa` の禁則を通したあとでも、読み返せばまだ直すところがあります。
規則になっていない直しです。朱入れは、行を直すたびに「もとの文 → 直した文」の対を残しているので、
それを語の単位で突き合わせて、**何を削り、何に言い換え、語尾をどう直したか**を集計します
（差分回収。`manuscript-qa` の③と同じ数えかたで、頻度二以上を規則候補にします）。

- **傾向表の頭**に、規則候補（二回以上）／一度きり（参考）／本人の領分（読点・語の足し・書き直し。規則にしない）が並びます
- **同じ直しを二回したら、次から先回りします。**「よく削る『静かに』」「語尾をよく直す『いた』→『く』」が
  鉛筆になり、その形が残っている行に引かれます。通しの種類にかかわらず出ます。設定で止められます
- **差分回収に渡せます。**「直しの回収（テキスト）」は集計、「差分回収に渡す二本」はもとの本文と直した本文の対。
  `manuscript-qa` の差分回収にそのまま渡せて、そこで立った頻度は `writing-style` の規則に上げられます

**過去の直しも持ち越せます。** 設定の「過去の直しを持ち越す」に、同じ作品の「直す前」と
「直した後」（Claudeが納めた原稿と、あなたが直した刊行版など）を入れると、文の単位で突き合わせて、
朱入れの中で直したのと同じ材料にします。作品をまたいで効くので、新しい原稿の一行目から先回りします。
Claudeとの別のチャットで直したものも、会話の記録は要りません。そのセッションで納められた原稿と、
あなたの最終版の二本があれば足ります。

初稿が残っていないときは、**差分メモ**でも入れられます。一行に一つ、「A → B」か「A を削除」。
末尾の「3件」「×3」は回数として数えます。メモの対は突き合わせずに、書いてあるとおりに数えます。
読めなかった行は、その場で数と例を出します。

**種類で束ねて、傾向にする。** 同じ文字列が二回そろうことは、実際にはあまりありません。
そこで直しの一つひとつを種類に分けて数えます——副詞を削る／主語・代名詞を落とす／つなぎの言葉を落とす／
直喩を削る／心理の名指しを削る／説明の語尾（のだった・のである）を落とす／漢字を開く・閉じる／
語尾を直す／読点を減らす、など。傾向表の頭に「種類でみた傾向」として、回数と例が並びます。

```
副詞を削る　23回（静かに 4、ゆっくりと 3、そっと 2、小さく、…）　先回り
主語・代名詞を落とす　15回（彼は 9、彼女の 4、…）　先回り
漢字を開く　40回（事 → こと 12、物 → もの 8、…）　先回り
```

**三回以上そろった種類は、その種類の語が一回きりでも鉛筆になります。**「静かに」「そっと」「ゆっくりと」を
一度ずつ削っていれば、副詞を削る傾向として三つとも先回りします。執筆に持っていく一枚にも、傾向として載ります。

**予測して、あらかじめ直す。** 傾向表の規則候補には「当てる ◯行」が付きます。押すと、その語句を含む行に
まとめて直しを入れます（確認が出て、例が三つ見えます）。当てた行はふつうの直しとして残るので、
緑で見えて、控えに「もと → 直し」が並び、一行ずつ元に戻せます。当てた分は癖としては数えません
（自分で自分を育てないため）。**語尾は当てません**——「鳴いた→鳴く」を「立っていた」に当てると
「立ってく」になる。活用が絡むものは鉛筆で指すまでです。一字のものも当てません。

**執筆時に気をつける。** 「執筆に持っていく」で、二回以上そろった癖を一枚にします。

```
【この書き手の直しの癖　執筆時に避けること】
出自：朱入れ　2026年9月8日　作品「人形の部屋」＋持ち越し（旧作A、旧作B）
・「彼は静かに」を書かない　4回（人形の部屋 2／旧作A 2）
・「のだった」で締めない　2回（旧作A 2）
```

Claudeに書かせるセッションの頭に貼れば、その癖を避けて書きます。`writing-style` の規則に上げるときは、
出自（作品名・日付・件数）ごと写してください——`manuscript-qa` の「出自タグ付きでしか正本へ追記しない」に合わせてあります。

感覚的な直しの大半は規則になりません。それでよく、この回収は感覚の中に混じっている
「実は型だったもの」だけを取り出すためのものです。

**傾向を見せる。** どの種類の指摘が何件残っているか、通しごとに何件直したか。

**消えないようにする。** 作品まるごとを一つのWordに控えます（`作品名_控え.docx`）。
本文は直しを反映し、直した行は緑、朱は赤、付箋は山吹。各区切りの控え（もとの文 → 直した文、
付箋と手触り、朱、覚え書き）も入ります。**端末のデータが消えても、Wordの側に残ります。**

いつ控えるかは三つから選べます。既定は**読む画面を離れるとき**（ひと続きの朱入れが終わるたびに一つ）。
区切りごとにも、押したときだけにもできます。印が一つもないうちは書き出しません。

パソコン（Chrome/Edge）なら、控えの置き場（フォルダ）を一度決めておけば、ダウンロードが増えず
**同じ一つのファイルに上書き**されます。次に開いたときも覚えています。

## 書き出し

| 書き出し | 中身 |
|---|---|
| 直した本文（テキスト） | 入稿用。区切りの印は入らず、原稿の改行のまま |
| 直した本文（Word） | 直した行は緑、朱を置いた行は赤 |
| 控え（Word／テキスト） | 「もとの文 → 直した文」、付箋（届いた案つき）、朱を置いた行、覚え書き |
| 相談票（テキスト） | 付箋の行＋前後二文＋覚え書き。Claudeに渡す紙 |
| 執筆に持っていく（テキスト） | 二回以上そろった癖を出自つきで一枚に。執筆の頭に貼る／writing-style に上げる |
| 直しの回収（テキスト） | 何を削り何に言い換えたかの集計。規則候補つき |
| 差分回収に渡す二本 | もとの本文と直した本文。`manuscript-qa` の差分回収の入力 |
| もとの本文（テキスト） | 読み込んだときのまま |

## 使いかた

パソコンでは `shuire.html` をブラウザで開く。`.docx` `.txt` `.md` を選ぶか、Wordから本文を貼りつけて
「区切って始める」。

**iPhoneでは、ファイルを直接開いても動きません**（Safari がスクリプトを走らせないため）。
URLで開ける場所に置く必要があります。claude.ai の非公開ページ（アーティファクト）として公開してあるので、
そのURLを iPhone の Safari で開き、「ホーム画面に追加」しておくと、アプリのように使えます。
原稿はその端末のブラウザの中にだけ置かれ、公開ページの側には残りません。

**iPhone と PC で同じものを見たいとき**は、設定の「claude.ai の保管庫に置いて揃える」を点けます。
点けると原稿・朱・付箋・直し・持ち越しが、あなたのアカウントだけに見える claude.ai の保管庫に置かれ、
同じページを開いた端末どうしで揃います（直した時刻の新しいほうが残り、履歴と持ち越しは足し合わさります）。
これは原稿を端末の外に置くということなので、**既定では切ってあり、点けるのはあなた**です。
点けたら、そのページを誰にも共有しないでください。

通信を使いたくないときは、設定の「持ち出す」で一枚の JSON にして、AirDrop などで運び、
もう片方の端末で「持ち込む」。新しいほうだけが取り込まれます。

公開用の一枚は `node tools/build-artifact.mjs 出力先.html` で組みます（claude.ai の枠が付ける
`<html>` `<head>` `<body>` を外した版）。枠の中では通常のダウンロードが効かないので、
Wordの控えなどの保存は枠の主に頼み、保存のたびに確認が出ます。確認の小窓（校了・割り直し・
当てる・消す）も、枠の中では標準のものが出ないため、画面の中の小窓にしてあります。

## 確かめかた

```bash
node tools/selftest.mjs    # 分割・復元・下読み・揃える・docxの読み書き（依存なし）
node tools/uitest.mjs      # 画面の通し（playwright が入っているときだけ）
```

## 触るときの約束

- 通信を足さない（CDN・API・解析ツールすべて）
- 原稿の本文を端末の外に出さない（「保管庫に置いて揃える」だけが例外で、点けるのは人。既定で点けない）
- 三つの印の意味を混ぜない（朱＝直すと決めた／付箋＝まだ決まっていない／鉛筆＝機械が引いた）
- 濃い背景に戻すなら、背景が効かない場合の見え方を先に確かめる
- 画面の言葉は同人・印刷の語彙のまま（区切り／通し／朱／鉛筆／控え／面付け）

くわしい設計の理由と地図は `docs/引き継ぎ.md` に。
